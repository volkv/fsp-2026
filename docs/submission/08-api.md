# Описание API

## Принципы

- **Версия и путь.** Публичный API — `/api/v1`, JSON в UTF-8, поля тел и ответов — `snake_case`. В пределах `v1` изменения только
  добавляющие; несовместимое изменение — новая версия `/api/v2`, а старая получает заголовки `Deprecation` и `Sunset`.
- **Один источник описания.** Каждая операция объявляется один раз: из объявления строятся обработчик маршрута и её часть документа
  OpenAPI 3.1 — схемы Zod запроса и ответа, способы аутентификации, требуемое право (`x-permission`), коды ошибок. Документ не
  редактируется руками и отдаётся приложением: `GET /api/v1/openapi.json`; интерактивная документация Swagger UI — `/api/docs`
  (собственные файлы, без внешних источников). Интеграционный тест проверяет, что каждый маршрут `/api/v1` описан и обслуживает
  именно описанную операцию, все ссылки схем разрешаются, у каждой операции описаны конверт ошибки и аутентификация.
- **Те же правила, что в интерфейсе.** API вызывает те же функции модулей, что и страницы: права, политика допуска компании,
  видимость кандидата и проекции карточки одинаковы. Выгрузки каталога целиком API не предусматривает.
- **Режим поиска виден клиенту.** Ответы каталога несут `search_mode` (`hybrid` или `fts_only`) и идентификатор пространства
  векторов, поэтому интеграция видит, что поиск идёт без модели.

## Аутентификация

| Способ | Кто | Как | Особенности |
|---|---|---|---|
| Сессия | браузер, все роли | cookie `__Host-session` (`HttpOnly`, `Secure`, `SameSite=Lax`) | небезопасные методы требуют `X-CSRF-Token` и проверки `Origin` |
| Ключ API | интеграции работодателя | `Authorization: Bearer fspk_<prefix>_<secret>` | права ключа — подмножество прав создателя; срок действия по желанию |
| Подпись ФСП | реестр ФСП | `X-FSP-Signature`, `X-FSP-Timestamp` | только маршрут вебхука ФСП |
| Секрет бота | Telegram | `X-Telegram-Bot-Api-Secret-Token` | только маршрут вебхука Telegram |

**Ключ API компании.** Создаёт владелец компании в кабинете (`/company/profile/keys`) со свежей аутентификацией; ключ
показывается один раз, на сервере хранится SHA-256 секрета и префикс для опознания. Права выбираются из тех, что разрешены ключам
и есть у создателя: каталог и карточки, потребности и подборки, вакансии, предложения и их пересмотр, этапы найма, рынок, пул
партнёра. Операции кандидата, персонала и управления ключами ключу недоступны. На каждом запросе проверяются отзыв и срок ключа,
активность членства создателя и политика допуска компании: приостановленная компания, удалённый сотрудник или отозванный ключ
теряют доступ немедленно. Создание и отзыв ключа пишутся в журнал действий.

В перечне операций ниже у каждой указан доступ: сессия, ключ API, подпись, без входа — и право.

## Ошибки

Любая ошибка — единый конверт:

```json
{
  "error": {
    "code": "validation_failed",
    "message": "Проверьте поля запроса",
    "request_id": "01J9Z6K7Q8R2S3T4V5W6X7Y8Z9",
    "details": [{ "path": "salary_min", "code": "too_small", "message": "Должно быть не больше salary_max" }]
  }
}
```

`request_id` совпадает с заголовком `X-Request-Id` ответа и полем журнала сервера.

| HTTP | `code` | Когда |
|---|---|---|
| 400 | `validation_failed` | тело или параметры не прошли схему; `details` — путь поля, код и сообщение |
| 401 | `unauthenticated` | нет сессии или ключа, ключ отозван или истёк |
| 403 | `forbidden` | нет права на действие; компания заблокирована политикой допуска — `details[].code` `company_suspended` или `company_rejected` |
| 403 | `csrf_failed` | запрос сессии без CSRF-токена или с чужим `Origin` |
| 404 | `not_found` | объекта нет **или** актор не вправе знать о нём (чужая компания, кандидат, которого функция видимости не показывает) |
| 409 | `conflict` | нарушение перехода состояния: ответ на заменённую версию условий, недоступный по политике грейда тест (код причины и дата `available_from`), открытое предложение той же паре |
| 409 | `idempotency_conflict` | повтор ключа идемпотентности с другим телом |
| 422 | `policy_violation` | нарушение продуктовой политики: вилка не в рублях, текст с дискриминационным требованием, неполный профиль компании, пауза перед повторным предложением и др. — код в `details[].code` |
| 429 | `rate_limited` | превышен лимит; `Retry-After` в секундах |
| 503 | `degraded` | зависимость недоступна, а безопасного режима у операции нет |

Сообщения ошибок не содержат персональных данных.

## Пагинация, идемпотентность, лимиты

- **Пагинация** — курсорная: `?cursor=&limit=` (`limit` до 100), в ответе `next_cursor`; конец списка — `null`.
- **Идемпотентность.** Операции, создающие ресурс (предложение, вакансия, потребность, ответ), принимают `Idempotency-Key`. Повтор с
  тем же ключом и тем же телом в течение 24 часов возвращает сохранённый ответ с заголовком `Idempotent-Replayed: true`; тот же
  ключ с другим телом — `409 idempotency_conflict`.
- **Лимиты частоты** — по ключу API и по адресу клиента, заголовки `RateLimit-Limit`, `RateLimit-Remaining`, `RateLimit-Reset`.
  Чтение каталога (поиск, карточка, кандидаты вакансии, пул партнёра) — 60 запросов в минуту на аккаунт, у ключа API — свой
  бюджет; выгрузка своих данных — 10 за 10 минут; вход через ФСП ID — 60 за 10 минут на адрес. Вебхуки ФСП и Telegram
  считаются отдельным правилом по адресу и не расходуют лимит API; отклонённая подпись тоже засчитывается.

## Вебхуки внешних систем

| Маршрут | Источник | Проверка | Ответ |
|---|---|---|---|
| `POST /api/v1/integrations/fsp/webhooks` | реестр ФСП | HMAC-SHA-256 от `{timestamp}.{rawBody}` секретом `FSP_WEBHOOK_SECRET`, расхождение времени до 5 минут, дедупликация по `X-FSP-Event-Id` | `202 { "accepted": true }`; тяжёлая работа — в задании `fsp.sync` (раздел «Интеграция с реестром ФСП») |
| `POST /api/v1/integrations/telegram/webhook` | Telegram Bot API | секрет заголовка `X-Telegram-Bot-Api-Secret-Token` | привязка чата по одноразовому токену, команда `/stop` |

Исходящие вебхуки для ATS работодателей — раздел «Интеграция с ATS работодателей».

## Основные группы операций

| Группа | Что умеет | Кто |
|---|---|---|
| Справочники | роли, навыки, грейды, справочник категорий | все |
| Каталог | поиск кандидатов по специализации, грейду, категории, стеку, достижениям ФСП, формату, региону, тексту; рынок категории; сравнение | работодатель (сессия или ключ) |
| Потребности и подборки | потребность текстом или формой с разбором, рекомендованные категории, подборка с разложением счёта, уточнения, «что если», отметки | работодатель |
| Вакансии | собственные вакансии с проверкой текста, черновик из текста, публикация, соответствие кандидатов вакансии | работодатель; чтение — все |
| Приглашения и найм | предложение с вилкой в рублях, версии условий и отличия, ответ кандидата, этапы и исход найма | работодатель; кандидат — ответ |
| Кандидат | профиль, опрос, подсказка и заявление грейда, тест, решения и возражения, категории, видимость, блок-лист, выгрузка своих данных | кандидат (сессия) |
| Квитанции | проверка квитанции и подтверждения категории без персональных данных, открытые ключи подписи | все, без входа |
| Оператор и администратор | модерация вакансий, конфликты возраста, пересмотр попыток, возражения, воронка, выпуски банка | персонал (сессия) |
| Интеграции | вебхуки ФСП и Telegram | по подписи |

Полный перечень сформирован из документа OpenAPI при сборке этой документации; рядом с PDF лежит сам документ `openapi.json`.
