# ФСП | Карьера

ФСП Карьера — платформа ИТ-найма, где навыки подтверждены.

Отраслевой агрегатор вакансий для ИТ-специалистов с обратной механикой подбора: профиль кандидата подтверждается результатами
соревнований по спортивному программированию и другими проверяемыми источниками, работодатель находит нужную категорию
специалистов и сам выходит на кандидата с вакансией и зарплатой.

## Запуск

Нужны Docker с Compose v2, `make` и git.

```sh
make up
```

Команда создаёт `.env` из `.env.example` (если его нет), собирает образы и поднимает весь стенд: PostgreSQL с pgvector,
Valkey (совместим с Redis), хранилище SeaweedFS, Mailpit, сервис разбора резюме `docparse`, песочницу исполнения кода `sandbox`, имитатор ФСП `fsp-mock`,
приложение и воркер фоновых заданий, и ждёт, пока все сервисы станут healthy. Контейнер приложения при старте применяет
миграции, публикует справочники таксономии (роли, навыки, грейды, правила проекции ФСП) и правовые документы из `legal/`
(редакции прототипа: оператор персональных данных не определён, его реквизиты — явные заглушки), продуктовые политики из
`policies/` (сроки ответа и найма, напоминания, пороги, хранение — продуктовые решения с указанным основанием) и источники
вакансий (выключены, пока их не включит администратор в кабинете `/admin/sources`; включение сразу ставит полный импорт), затем запускает сервер; воркер стартует после него из того же образа. Первая сборка — несколько
минут (образы тулчейнов песочницы и LibreOffice). Приложение — http://localhost:57300, проверка состояния —
http://localhost:57300/api/health. Остановить — `make down`.

Песочнице нужен хост Linux с cgroup v2 (`stat -fc %T /sys/fs/cgroup` → `cgroup2fs`).

Вход через ФСП ID на стенде идёт через имитатор (http://fsp-mock.localhost:57610): страница входа предлагает
демо-учётки синтетических спортсменов с достижениями на реальных соревнованиях ФСП. Переключение на настоящий ФСП ID —
сменой `FSP_ID_ISSUER`, `FSP_ID_CLIENT_ID` и `FSP_ID_CLIENT_SECRET`.

Регистрация — по почте и паролю или после входа через ФСП ID, одним потоком: роль (кандидат или работодатель), дата
рождения или компания, соглашения, затем согласие на обработку данных на отдельной странице. Письма стенда (подтверждение
почты, сброс пароля) — в Mailpit: http://localhost:57825.

Разработка с горячей перезагрузкой, команды, порты и соглашения — в [`docs/development.md`](docs/development.md).
Полная проверка (линтеры, типы, unit, integration, сборка, e2e, образы) — `make check-all`.

## Демо-учётки

Стенд https://fsp-career.volkv.com работает на демо-данных: люди и компании вымышленные, соревнования — реальные соревнования
ФСП. Сценарий в двух строках: рекрутер «Северного кода» вставляет текст вакансии, видит пул подтверждённых кандидатов и
рынок, сравнивает кандидатов, открывает квитанцию ФСП и приглашает кандидата с вилкой; кандидат принимает приглашение и
раскрывает контакты, стороны отмечают этапы найма, оператор ФСП видит воронку карьерных исходов. Каждую ночь в 00:00 UTC
стенд возвращается к засеянному состоянию.

### Демо-сессии судей

На демо-стенде (`DEMO_MODE=true`) вход — страница `/demo`: выберите роль сценария (кандидаты К-1…К-5, работодатели
Ю-1…Ю-3, оператор ФСП, администратор). Для каждого посетителя создаётся своя демо-сессия — копия героев, компаний и их
данных: приглашения, ответы, найм и возражения одного посетителя не видны другим. Роли переключаются на той же странице
и не расходуют лимит новых сессий (60 в сутки с одного адреса); ссылка оттуда открывает ту же сессию в другом браузере.
Сессия без действий удаляется через 8 часов и не позже чем через 24 часа (`retention_policy.demo_session_hours`) — целиком,
заданием `demo.purge`; в любом случае — при ночном сбросе в 03:00 МСК.

Своё резюме судья загружает на `/demo/resume` — только с отдельным согласием; профиль уходит из каталога, резюме и всё
полученное из него удаляются через 24 часа. Оператор и администратор демо-сессии видят и решают только дела своей сессии;
загрузка пакета результатов ФСП, режим моделей и роли персонала в демо недоступны.

## Модели

Модели помогают, но ничего не решают: каждый извлечённый факт подкреплён цитатой из документа и проверяется кодом, категория
кандидата от моделей не зависит, без них продукт работает целиком в явном упрощённом режиме.

- **Разбор текста** (резюме, потребность работодателя, вставленная вакансия) — по умолчанию внешняя модель **Gemini Flash
  (Google)** через OpenAI-совместимый шлюз: `LLM_BASE_URL=https://llmgate.volkv.com/v1`, `LLM_MODEL=gemini-flash:latest`, ключ —
  в `LLM_API_KEY` (в репозитории его нет; без ключа текст разбирают правила). Текст при этом уходит провайдеру модели — это
  сказано в согласии на обработку данных, в подписи у загрузки резюме и у поля текста потребности и в метке у каждого результата
  разбора.
- **Своя модель на одной видеокарте** — vLLM с `Qwen3-8B-AWQ`, текст не покидает платформу: `LLM_RUNTIME=vllm` и адрес сервера.
  Подходит и любой другой OpenAI-совместимый API со `strict` JSON Schema — переменными `LLM_*`, без правки кода.
- **Эмбеддинги** — свой сервис `embedder` на CPU (llama.cpp, bge-m3) в `compose.yaml`; **переранжирование** (`RERANK_*`) —
  необязательно.

Режимы, куда уходят данные, замеры задержки и качества, запуск своей модели — [`docs/models.md`](docs/models.md).

## Стек

- SvelteKit 2 и Svelte 5 (runes), TypeScript strict, Tailwind CSS 4, adapter-node, Node 24, pnpm.
- PostgreSQL 17 с pgvector, Drizzle ORM и drizzle-kit; Valkey (совместим с Redis); S3-совместимое хранилище (SeaweedFS на стенде); SMTP (Mailpit на стенде).
- Zod для схем и валидации окружения.
- Фоновые задания — очередь в PostgreSQL (`FOR UPDATE SKIP LOCKED`, аренда с пульсом, условная запись результата по
  ревизии входа, повторы с backoff) и отдельный процесс-воркер с планировщиком периодических заданий на advisory lock.
- Разбор резюме (PDF, DOCX, RTF, DOC, ODT, сканы) — отдельный сервис `docparse` на Python 3.13: pdfplumber, python-docx,
  LibreOffice headless, Tesseract; изолирован от сети и данных, контракт — `contracts/docparse/v1.schema.json`.
- Песочница исполнения кода для практических заданий — go-judge с Python, JavaScript, TypeScript, Go, C++ и Java:
  каждый запуск в своих пространствах имён без сети с лимитами cgroup, контейнер — во внутренней сети только со шлюзом;
  нужен хост с cgroup v2.
- Имитатор ФСП `fsp-mock` на Node 24 и `oidc-provider`: ФСП ID (OIDC, как у `sso.fsp-russia.ru`) и API достижений
  с вебхуками; контракт — `contracts/fsp-achievements/v1.schema.json`.
- Проверки: ESLint, Prettier, svelte-check, Vitest (unit и integration через Testcontainers), Playwright; для `docparse` —
  ruff и pytest.
