# Банк семейств заданий

Задания теста на грейд (`docs/domain.md`, раздел 10). Семейство — шаблон задания одного блока компетенций: по сиду, грейду и
классу существенных параметров генератор строит экземпляр, и правильный ответ считает код, а не человек.

> **Банк открыт только в рамках хакатона — ради прозрачности проверки.** В эксплуатации банк — закрытые данные: опубликованное
> семейство считается скомпрометированным и выводится из ротации, банк пополняется фабрикой семейств. Устойчивость к утечке
> заявляется для конкретного выпуска банка, не для этого дерева.

## Устройство

```
assessments/families/
  <специализация>/<ключ семейства>/
    descriptor.json     FamilyDescriptor контракта (src/lib/server/assessments/contract/bank.ts), вместе с отчётом ворот gates
    generator.ts        generate({seed, grade, classId}) → ItemInstance; у QA ещё harness(instance, mode, part); для ворот — build()
  _lib/                 общий код генераторов: поток случайных чисел от сида, SQL, сравнение ответов, сборка экземпляра
  _probes/<специализация>/<ключ>/   пробы механизмов в том же формате: проходят ворота, в выпуск не идут
  gate-sources.json     хэш исходников, с которыми каждое семейство последний раз прошло ворота
  gates-report.md       отчёт последнего полного прогона ворот
```

Движок теста читает дерево сам (`src/lib/server/assessments/families.ts`): папки на `_` — не семейства. Генератор — чистая
детерминированная функция: только поток `instanceRng` от ключа, версии, грейда, класса и сида. Кроме `generate`, он экспортирует
`build` — экземпляр и, лениво, материал ворот: как доказать ответ (`reference`) и как выглядит каждое ошибочное решение на этом
экземпляре (`wrong`). У QA `harness(instance, mode, part)` — программа на Python: кейсы кандидата JSON `[{input, expected}]` на входе,
одна строка из `0`/`1` на выходе — по символу на кейс на исправном эталоне или на мутант в порядке экземпляра.

## Как ворота доказывают ответ

Программы на Python исполняются рантаймом образа песочницы (`services/sandbox`, тот же Python и SQLite, что у кандидатов).

| Формат          | Ответ считает                                                    | Ворота проверяют                                                                                                                                                                                                                                           |
| --------------- | ---------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `code_trace`    | модель генератора на TS                                          | показанная программа, запущенная настоящим Python, печатает тот же ответ                                                                                                                                                                                   |
| `sql_trace`     | запрос, исполненный SQLite в Node (`_lib/sql.ts`)                | тот же скрипт через `sqlite3` Python даёт те же строки                                                                                                                                                                                                     |
| `compute`       | модель на TS                                                     | независимая эталонная программа на Python даёт тот же ответ                                                                                                                                                                                                |
| `bug_locate`    | номер строки дефекта                                             | с дефектом программа не проходит проверки спецификации, с исправленной строкой — проходит; правка «соседней» строки не чинит                                                                                                                               |
| `practice_code` | скрытые тесты от генератора                                      | эталон проходит все группы; ошибочные программы проваливают хотя бы одну; тесты убивают шаблонные мутанты эталона; эталон одного класса не проходит тесты другого                                                                                          |
| `qa_mutation`   | набор мутантов и их эквивалентность (перебор всей области входа) | кейсы автора в бюджете 5–8 проходят на эталоне и убивают всех неэквивалентных мутантов; эквивалентность подтверждена перебором в Python; слабые наборы (только типичные значения, неверный ожидаемый ответ, перебор сверх бюджета) не получают полный балл |

Пороги — `FAMILY_GATES` контракта; сверх них фабрика требует: ошибочное решение отвергается на **каждом** экземпляре, к которому
применимо; на каждом уровне применимо хотя бы одно; один и тот же сид в двух классах даёт разные ответы не чаще 5 % (кроме номеров строк).

## Добавить семейство

1. Папка `<специализация>/<ключ>/` с `descriptor.json` и `generator.ts`, ключ `<блок>.<имя>`; образцы — `be.lang.closure-capture`
   (трассировка), `be.db.null-aggregates` (SQL), `be.api.retry-backoff` (расчёт), `be.debug.spec-violation` (поиск дефекта),
   `be.code.order-summary` и `be.code.rate-limiter` (практика, у второй — шаг «измени своё решение»), `_probes/qa/…` (QA).
   В `gates` нового описания — нули: их заполнит прогон.
2. `node scripts/assessments/gates.ts --local-python --no-write --family <ключ>` — пока не `ok`.
3. `pnpm bank:gates --family <ключ>` пишет отчёт в `descriptor.json` и хэш в `gate-sources.json`.
4. Ревью и оценки порога — ниже, «Ревью и Angoff». Юнит-тест банка (`scripts/assessments/bank.test.ts`) ловит семейство,
   чьи исходники изменились после прогона ворот.

## Прогнать ворота

```bash
pnpm bank:gates                          # все семейства и пробы, образ песочницы (собирается из services/sandbox, из кэша — быстро)
pnpm bank:gates --family be.db.          # по префиксу ключа
pnpm bank:gates --pending-review-ok      # код 0, если остались только ревью рубрик человеком
node scripts/assessments/gates.ts --local-python --no-write --family be.lang.   # быстрый цикл: python3 машины, без записи
```

По 200 сидов на каждый класс каждого уровня. Отчёт — `gates-report.md`: по семействам (отказы эталона, пойманные ошибочные
решения, коллизии, пересечение классов, мутанты, перенос), проблемы валидатора контракта и банковая сторона выпуска: опорные классы,
не меньше 4 семейств за каждым блок-тестом (`blockTestPairs`), вместимость всех крайних историй кандидата (`capacityChecks`: две
попытки на грейд, блок-тесты из вакансий, перепроверки). Симуляцию траекторий выпуска делает движок теста (`pnpm bank:check`).

## Классы

У каждого семейства-уровня — классы `A` и `B` (формы теста на грейд), опорный `anchor` (общий для обеих форм) и резервный `X`:
его не подают в тесте на грейд, им пользуются блок-тест работодателя и перепроверка на созвоне. Каждый класс — свой путь решения
(другое значение существенного параметра), а не перекраска условия.

## Ревью и Angoff

Рубрику и эталон проверяют, а порог уровня оценивают **независимые рецензенты** — модели разных линеек или люди команды, но не авторы
семейства. Для выпуска нужны два одобрения моделей разных линеек или одно одобрение человека на текущих исходниках и ни одного запроса
изменений; у каждого уровня — не меньше двух независимых оценок Angoff (шаг 0,05), порог — их среднее на шкале 1/20 (половина — вверх).
Суждения привязаны к `sourceSha256` — хэшу описания без отчёта ворот и оценок плюс текста генератора (`familySourceSha256` контракта):
правка семейства их сбрасывает, прогон ворот убирает устаревшие.

```bash
node scripts/assessments/review-pack.ts --out <папка> --family be.db. [--seeds 2]   # пакет рецензенту: .md и шаблон .review.json
node scripts/assessments/record-review.ts <папка>/*.review.json                       # записать заполненные ревью в описания
```

Пакет — слепой раунд: в нём нет ни чужих оценок, ни предварительного порога. Ревью на других исходниках, ревью автора и ревью без
оценки каждого уровня не записываются; повторное ревью той же линейки заменяет прежнее; расхождение оценок больше 0,2 — сигнал ко
второму раунду.

Пока независимых оценок нет, `ratings` пуст, а `mean` хранит **предварительный порог авторов** — его видит движок при выборе
заданий; ворота считают такие уровни ожидающими оценщиков (не дефектом), выпуск их не допускает. У практики предварительный порог
0,8: практика — ворота, которые пограничный кандидат проходит (контракт требует 0,75–0,90).
