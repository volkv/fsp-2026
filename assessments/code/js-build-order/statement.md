В монорепозитории десятки тысяч пакетов, и у каждого есть зависимости внутри репозитория. Система сборки должна выдать детерминированный порядок: пакет собирается только после всех своих зависимостей, а из готовых к сборке первым идёт пакет с лексикографически меньшим именем.

## Вход

Один JSON-объект:

```
{ "packages": { "app": ["ui", "core"], "ui": ["core"], "core": [] } }
```

- ключи `packages` — имена пакетов: от 1 до 50 символов из латинских букв, цифр и `@/._-`; пакетов от 1 до 20 000;
- значение — список зависимостей пакета; в сумме по всем пакетам не больше 100 000 элементов; зависимость может повторяться в списке, пакет может зависеть сам от себя.

## Выход

Проверки идут по порядку, выводится результат первой сработавшей.

1. **Неизвестные зависимости.** Если какой-то пакет зависит от имени, которого нет среди ключей `packages`, выведите для каждой такой пары строку `MISSING <пакет> -> <зависимость>`. Пары без повторов, упорядочены по пакету, затем по зависимости. Больше ничего не выводится.
2. **Порядок сборки.** Иначе выведите пакеты по одному в строке в порядке сборки: на каждом шаге среди ещё не собранных пакетов, все зависимости которых уже собраны, выбирается лексикографически меньший.
3. **Цикл.** Если на каком-то шаге готовых пакетов нет, а несобранные остались, после уже выведенного порядка выведите строку `CYCLE:` и через пробел все несобранные пакеты в лексикографическом порядке.

Лексикографический порядок — посимвольное сравнение кодов символов, как у `Array.prototype.sort()` без компаратора.

## Пример 1

Вход:

```
{"packages":{"app":["ui","core","ui"],"ui":["core"],"core":[],"docs":[]}}
```

Выход:

```
core
docs
ui
app
```

## Пример 2

Вход:

```
{"packages":{"a":["b"],"b":["c"],"c":["b"],"d":[],"e":["a"]}}
```

Выход:

```
d
CYCLE: a b c e
```

## Ограничения

Лимит — 2 секунды процессорного времени на тест. Решение, которое на каждом шаге заново перебирает все пакеты, на больших тестах не уложится.
