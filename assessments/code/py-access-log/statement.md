Сервис пишет журнал запросов: одна строка — один запрос. Нужна короткая сводка для дежурного инженера.

## Вход

В первой строке — число `N` (0 ≤ N ≤ 100 000). Далее `N` строк вида

```
METHOD PATH STATUS DURATION_MS
```

- `METHOD` — HTTP-метод (`GET`, `POST`, …);
- `PATH` — путь без пробелов, например `/api/orders`;
- `STATUS` — код ответа, целое от 100 до 599;
- `DURATION_MS` — длительность в миллисекундах, целое от 0 до 10⁹.

Поля разделены одним или несколькими пробелами.

## Выход

Ровно семь строк:

```
1xx: <число>
2xx: <число>
3xx: <число>
4xx: <число>
5xx: <число>
slowest: <PATH> <DURATION_MS>
top: <PATH> <COUNT>
```

- Первые пять строк — сколько запросов закончилось кодом из каждого класса.
- `slowest` — самый долгий запрос. Если таких несколько, берётся лексикографически меньший путь.
- `top` — самый частый путь и число запросов к нему. При равенстве — лексикографически меньший путь.
- Если `N = 0`, в строках `slowest` и `top` вместо пути и числа стоит один символ `-`.

## Пример

Вход:

```
5
GET /api/orders 200 35
POST /api/orders 201 120
GET /api/orders/7 404 3
GET /health 200 1
GET /api/orders 500 900
```

Выход:

```
1xx: 0
2xx: 3
3xx: 0
4xx: 1
5xx: 1
slowest: /api/orders 900
top: /api/orders 3
```
