Офисный бот бронирования переговорок получает выгрузку существующих броней и пачку вопросов «свободна ли комната в такой-то промежуток». Нужно ответить на вопросы и посчитать, сколько минут каждая комната занята.

Время — целое число минут от начала отсчёта. Бронь и запрос — полуинтервалы `[start, end)`: бронь `[60, 120)` и запрос `[120, 180)` не пересекаются.

## Вход

В первой строке — числа `N` и `Q` (0 ≤ N ≤ 100 000, 1 ≤ Q ≤ 100 000).

Далее `N` строк брони: `ROOM START END`. Затем `Q` строк запросов: `ROOM FROM TO`.

- `ROOM` — имя комнаты: латинские строчные буквы, цифры и дефис, от 1 до 20 символов;
- `0 ≤ START < END ≤ 10⁹`, `0 ≤ FROM < TO ≤ 10⁹`.

Брони одной комнаты могут пересекаться и повторяться — выгрузка собрана из нескольких календарей. В запросе может встретиться комната, у которой нет броней.

## Выход

Сначала `Q` строк — ответы на запросы по порядку: `BUSY`, если промежуток пересекается хотя бы с одной бронью этой комнаты, иначе `FREE`.

Затем для каждой комнаты, у которой есть хотя бы одна бронь, в лексикографическом порядке имён — строка `ROOM MINUTES`: сколько минут комната занята, пересекающиеся брони считаются один раз.

## Пример

Вход:

```
4 4
blue 60 120
blue 90 150
green 0 30
blue 200 210
blue 150 200
blue 149 151
red 0 10
green 30 45
```

Выход:

```
FREE
BUSY
FREE
FREE
blue 100
green 30
```

Промежуток `[150, 200)` у `blue` свободен: первые две брони дают занятость `[60, 150)`, следующая начинается в 200.

## Ограничения

Лимит времени — 2 секунды процессорного времени на тест. Решение, которое для каждого запроса перебирает все брони, на больших тестах не уложится.
