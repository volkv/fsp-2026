Сервис каталога держит в памяти кэш карточек товаров: ограниченной вместимости, с вытеснением давно не использованных записей (LRU) и временем жизни у каждой записи (TTL). Нужно воспроизвести поведение кэша по журналу операций.

## Правила

Кэш вмещает `C` записей. Время — целые миллисекунды; операции идут в порядке неубывания времени.

- Запись, положенная в момент `T` с временем жизни `TTL`, **истекает** в момент `T + TTL`: начиная с этого момента её нет в кэше, она не занимает место и не участвует в вытеснении.
- **Использование** записи — её успешное чтение `GET` или запись `PUT`. LRU-запись — та, что дольше всех не использовалась.
- `PUT T KEY VALUE TTL`: если `KEY` есть в кэше (и не истёк) — значение и срок заменяются, запись становится использованной. Иначе, если кэш заполнен, из него вытесняется LRU-запись и печатается `EVICT <ключ>`; затем новая запись добавляется. Больше `PUT` ничего не печатает.
- `GET T KEY`: печатает значение и делает запись использованной; если записи нет или она истекла — печатает `MISS`.
- `DEL T KEY`: удаляет запись и печатает `OK`; если записи нет или она истекла — `MISS`.

## Вход

В первой строке — `C` и `N` (1 ≤ C ≤ 1000, 1 ≤ N ≤ 20 000). Далее `N` строк-операций в формате выше.

- `0 ≤ T ≤ 10¹²`, `1 ≤ TTL ≤ 10¹²`;
- `KEY` и `VALUE` — от 1 до 20 символов из латинских букв, цифр, `_`, `-` и `:`.

## Выход

Строки, которые печатают операции, по порядку. В конце — две строки о состоянии кэша в момент последней операции:

```
SIZE <число записей>
KEYS <ключи от последней использованной к LRU через пробел>
```

Если кэш пуст — `KEYS -`.

## Пример

Вход:

```
2 9
PUT 0 a 1 100
PUT 10 b 2 1000
GET 20 a
PUT 30 c 3 1000
GET 40 b
GET 99 a
GET 100 a
PUT 110 d 4 5
DEL 115 d
```

Выход:

```
1
EVICT b
MISS
1
MISS
MISS
SIZE 1
KEYS c
```

`GET 20 a` сделал `a` использованной, поэтому при `PUT 30 c` вытеснена `b`. В момент 100 запись `a` истекла. Запись `d` истекла в 115 — `DEL` её уже не находит.
